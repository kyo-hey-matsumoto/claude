# オートスピリット 配車・在庫ボード — 開発引き継ぎ資料

## 概要

保険代車(ASレンタカー)とtoCレンタカー(横浜レンタカー)の車両ステータス・配車・引取・在庫管理を一元化するツール。現在はClaudeアーティファクト(React)のプロトタイプとして動作しており、Pro プランの「Publish」機能で先方(クライアント)と公開URLを共有し、実データとして運用を試している段階。

**現在のソース**: `vehicle-status-board-v5.jsx`(このファイルと同梱)

---

## ⚠️ Claude Codeで移行・開発する際の最重要注意点

現在のプロトタイプは `window.storage`(get/set/shared:true)というAPIでデータを保存している。これは **Claude アーティファクト環境専用のAPI** であり、Claude Codeで作るスタンドアロンアプリやWebサービスでは動作しない。

Claude Codeで開発を継続する場合、この永続化層を以下のような一般的な手段に置き換える必要がある:
- バックエンド + DB(例: Node.js/Express + SQLite や PostgreSQL、Supabase 等)
- 認証・複数ユーザーでのリアルタイム共有をどう実現するか(現状は`shared:true`で全員が同じデータを見る前提の設計)

データモデル自体(下記スキーマ)はそのまま流用可能。置き換えが必要なのは永続化とリアルタイム同期の実装部分のみ。

## データモデル

### vehicle オブジェクト

```
{
  id: string,
  number: string,          // 車両番号(例: "6643")
  model: string,           // 車種(例: "ポロ")
  note: string,            // 車両メモ
  status: "available" | "out" | "cleaning",  // 生の状態(下記「ステータス設計」参照)
  location: string,        // 現在の拠点。"川和" | "青葉" | "新横浜"
  transfer: null | {       // 回送予定(在庫ありの車両のみ設定可)
    from: string, to: string, date: "YYYY-MM-DD", staff: string, note: string, createdAt: number
  },
  specialStatus: null | {  // 車検・故障・板金の特別ステータス(status を上書きする)
    type: "車検" | "故障" | "板金",
    stage: "wait" | "in",  // 提出待ち / 中
    note: string, startedAt: number
  },
  currentDispatch: null | {   // 稼働中(out)のときの配車情報
    date: "YYYY-MM-DD",       // 配車日(=出発地確定時点の拠点を departureLocation として保持)
    time: string,             // 出発時刻。空文字なら「出発時刻未定」
    category: "対物" | "自費" | "長期レンタル",
    contractDays: number | null,  // 対物=15or30、自費=14固定、長期レンタル=null(上限なし)
    staff: string,             // 担当者(自由記述、複数可)
    requester: string,         // 依頼元
    note: string,
    departureLocation: string  // 配車完了の瞬間の location を自動記録(手入力ではない)
  },
  pickupSchedule: null | {   // 引取予定(稼働中の車両に対して登録)
    date: "YYYY-MM-DD", returnLocation: string, staff: string, note: string
  },
  pickupCompletedAt: number | null,  // 引取完了確定時のタイムスタンプ(清掃待ち中に表示)
  reservations: [            // 未来の配車予約(複数可)
    { id, date, time, category, contractDays, staff, requester, note, createdAt }
  ],
  updatedAt: number,
  updatedBy: string
}
```

## ステータス設計

### 通常フロー(5段階、車両1台につき同時に1つ)

```
在庫あり(available) → 配車予定(scheduled, 自動判定) → 稼働中(out)
   → 引取待ち(pending_pickup, 自動判定) → 清掃待ち(cleaning) → 在庫あり
```

- 「配車予定」「引取待ち」は保存された生ステータスではなく、**日付の自動判定による導出ステータス**(`getViewStatus`関数を参照)。
  - `reservations` に今日以前の日付の予約があれば「配車予定」
  - `status==="out"` かつ `pickupSchedule.date` が今日以前なら「引取待ち」

### 特別ステータス(車検・故障・板金、通常フローに優先して上書き)

```
(何らかのstatusから) → ○○提出待ち(wait) → ○○中(in) → 完了・在庫あり
```

`specialStatus` がセットされている間は、通常のステータス計算より **常に優先** して表示される(`getViewStatus`の最初の分岐)。稼働中など、どの状態からでも開始できる設計。

**✅確定(2026-07-15)**: 車検・故障・板金中の車両は、仮抑え計算(14日/15日/30日ルール)から**完全に除外する**。これらの状態にある車両は保険代車の在庫候補になり得ないため。

## 主要ビジネスルール

1. **保険代車の返却日は本質的に予測不可能** という前提のもと、「予測」ではなく「確定した瞬間にデータを反映する」設計方針(イベント駆動)を採用。
2. **仮抑え(在庫ブロック)の期間**:
   - 対物: 特約15日 or 30日(依頼時に先方から通知される)
   - 自費: 特約という概念がないため固定14日
   - 長期レンタル: 上限なし(返却まで無期限に在庫を抑える)
3. **予約は開始日のみ必須**。返却日は入力させない(現場の「引取完了」操作で確定させる思想)。
4. **出発時刻は空欄可**。空欄の場合は「出発時刻未定」と表示。
5. **拠点表示の切り替え**:
   - 稼働中(out)のときは「拠点」ではなく「出発地」と表示。値は配車完了の瞬間の拠点を自動記録したもの(`currentDispatch.departureLocation`)。手入力ではない。
   - 引取完了時に選択した「返却場所」が、そのままその車両の最新の `location` になる。
6. **回送(拠点間移動)**:
   - 個人予約対応などでtoC車両を店舗間で動かす際の指示を記録する機能。
   - **在庫あり(available)の車両のみ**回送を入力可能(稼働中の車両には非表示)。
   - **✅確定(2026-07-15)**: 回送予定が入っている車両は、保険代車の在庫候補から**除外する**。回送中でも見た目の`status`は`available`のままだが、保険代車向けの仮抑え・在庫計算ロジックでは「在庫あり」とみなさない。
7. **引取完了フロー**:
   - 「引取完了にする」ボタン押下 → 現在時刻表示 + 返却場所選択の確認モーダル → 確定で初めて処理が進む(誤操作防止)。
   - 引取連絡を事前登録していない場合も、この確認モーダルで返却場所を選ばせる。

## 画面構成(タブ)

同一データソース(vehicles配列)を参照する3タブ構成:

1. **在庫ボード**: 日付ピッカーで未来日を選択すると、その日時点の予測ステータスを表示(14日/15日/30日ルールに基づく)。今日以外は操作ロック。
2. **今日のタスク**: 配車予定・引取予定・回送予定を担当者ごとにグルーピングして一覧表示(担当者は「松、羽」のようなカンマ/読点区切りの自由記述をパースして複数人に紐付け)。タスクをタップすると車両詳細シートが開く。
3. **車両マスタ**: 全車両一覧。車両を選ぶと車両詳細シートが開き、車検・故障・板金のステータスを(現在のステータスに関わらず)開始・進行・完了できる。
