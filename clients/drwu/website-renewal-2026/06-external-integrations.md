## データ設計（概要）

主要エンティティと連携関係の概略（詳細ER図は開発フェーズで作成）。

```
顧客(Customer)
 ├─ LINE友だちID（LINE連携アプリ経由で紐付け）
 ├─ ポイント残高（LINE連携アプリ or Shopify標準メタフィールドで保持）
 ├─ 注文履歴(Order) ── 商品(Product) ── 商品タグ(悩み軸/シリーズ軸)
 └─ 会員ステータス（新規/継続/誕生日情報）

商品(Product)
 ├─ シリーズタグ（マンデリック/ヒアルコンプレクス/…）
 ├─ 悩みタグ（毛穴/乾燥/くすみ/ハリ/敏感肌/UV）※複数付与可
 └─ セット構成（バンドルアプリ側で単品↔セットの対応を保持）

キャンペーン(Campaign)
 └─ 種別（初回限定/LINE特典/セット特典/季節企画）、掲載期間
```

### 商品タグ設計の前提

- 現行商品には「シリーズ」の分類はあるが「悩み」の分類がないため、FR-03（肌悩み別導線）の実装には**商品タグの新規設計・全SKUへの付与**が前提条件になる
- 1商品が複数の悩みタグを持つケースがある（例: マンデリックは「毛穴・ざらつき」「くすみ・透明感」の両方に該当）

## 非機能要件

| 区分 | 要件 | 備考 |
|---|---|---|
| パフォーマンス | TOPページのセクション数増加後も表示速度（LCP等のCore Web Vitals）を現状同等以上に維持する | 画像の遅延読み込み・セクションの段階描画を検討 |
| 計測 | TOP各セクション（①〜⑧）でのクリック率・コンバージョンをGA4イベントで取得できること | F-14。改善のPDCAに必須 |
| SEO | コレクション統廃合・URL変更時は301リダイレクトで既存の評価を継承する | FR-11。レガシーコレクション整理時に必須 |
| セキュリティ・個人情報保護 | LINE連携・会員登録で扱う個人情報（氏名・誕生日・購入履歴・LINE友だちID）を適切に管理する。プライバシーポリシーの記載更新を伴う | 既存 `/policies/privacy-policy` の見直しが必要 |
| 可用性 | Shopifyプラットフォームおよび導入アプリのSLAに準拠する（自社での特別な可用性対策は行わない） | Shopify標準機能・Shopifyアプリの範囲内 |
| 保守性 | キャンペーンバナー・コラム・使い方ガイド等の更新は、エンジニアを介さず運用担当者が行えること | Shopify標準ページ/メタフィールドでの運用を基本方針とする |
| 拡張性 | 将来的な多言語対応・海外展開（現時点ではスコープ外）を著しく阻害しない設計とする | 対象外事項だが設計時に配慮 |
| アクセシビリティ | 主要導線（肌悩み別・シリーズ別・ランキング）はスマートフォンでの操作性を優先して設計する | ターゲットユーザーの主要デバイスを想定 |

## 未確定事項（要すり合わせ）

- LINE連携アプリの最終選定（CRM PLUS on LINE／StoreCRM）と、対象ID数に応じたコスト試算
- バンドル/セット販売アプリの選定と在庫連動方式
- ランキングの集計方式（アプリ自動集計／運用者による手動更新）
- GA4の導入状況・既存の計測設計の有無
